## Overview

The UPI Shield is a proactive fraud prevention engine integrated directly within mobile payment client architectures. Its primary goal is to address the rapid rise of social engineering scams in India's peer-to-peer digital payment ecosystem. By combining local device heuristics with backend machine learning model scoring, the system detects suspicious request patterns, alerts users before transactions are confirmed, and protects vulnerable user cohorts from financial exploitation.

This case study outlines the end-to-end design process, technical challenges, and product metrics associated with building a real-time defensive overlay. The system aims to mitigate fraud without introducing unnecessary friction for day-to-day verified transactions, striking a delicate balance between security enforcement and user experience consistency.

## Problem

<CalloutBox type="problem">
  UPI fraud has transitioned from technical exploits to social engineering tactics. Attackers leverage user trust and behavioral urgency to trick them into authorizing fraudulent transfers, typically by misrepresenting PIN authorization dialogs.
</CalloutBox>

Traditional payment apps treat security as a binary gate at the end of the transaction flow. When scammers mask payment requests under fake "Cashback Reward" or "Refund Processing" banners, users input their secret UPI PIN without realizing they are sending money instead of receiving it.

To address this challenge, we needed to solve three core sub-problems:
- **Lack of Contextual Awareness**: Standard UPI transactions do not differentiate between transferring to a familiar peer and sending to a newly registered account requesting money.
- **Cognitive Distraction**: Scam UI layouts are optimized to confuse users and distract them from verification warnings.
- **Urgency Exploitation**: Scammers use live phone calls or timer overlays to create high pressure, forcing quick decisions.

<CalloutBox type="insight">
  Users rarely read warning labels when they are in a high-stress or high-urgency state. Defensive overlays must utilize structural friction—like forced interaction halts or pattern mismatches—to break the user's auto-pilot mindset.
</CalloutBox>

## Approach

We adopted a phased approach to design a solution that integrates real-time ML risk scoring with an intuitive intervention framework.

<Accordion items={[
  {
    title: "Discovery Phase",
    children: (
      <>
        <p>During discovery, we reviewed over 5,000 fraud records in bank logs. We discovered that most fraud transactions occur on newly created accounts with highly asymmetrical send/receive ratios.</p>
        <p>We conducted 12 remote interviews with scam victims to map the emotional journey from the initial alert to the realization of financial loss.</p>
      </>
    )
  },
  {
    title: "Ideation Phase",
    children: (
      <>
        <p>The product and design teams brainstormed multiple security interventions, including multi-factor SMS codes, delayed transfers, and interactive security screens.</p>
        <p>We decided on a dynamic contextual overlay system that adjusts visual warning friction depending on the calculated risk level of the transaction destination.</p>
      </>
    )
  },
  {
    title: "Validation Phase",
    children: (
      <>
        <p>We created interactive prototypes in Figma simulating fraudulent cashbacks and QR codes. We tested these prototypes on a cohort of 30 elderly and non-tech-savvy users.</p>
        <p>Testing showed that introducing a mandatory 3-second hold and visual checklist reduced accidental PIN submission by 93%.</p>
      </>
    )
  }
]} />
